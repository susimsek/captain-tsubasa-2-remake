## Claim and source identity

On the supplied ROM, confirming PASS and selecting the adjacent teammate advances from the receiver prompt to a new command-input wait with that teammate as holder. This is a FCEUX observation, not yet a Godot implementation or parity claim.

- ROM SHA-256: `4f1f74d495e86025a5ad17fec2c171f37a94541a7d8ff7034c580d7d5111a097` (MD5 `eaf2b3745263efa4b1afd2b400f68dae`), mapper 4 / MMC3.
- FCEUX 2.7.0, NTSC, NewPPU, sound muted. Frame numbers are FCEUX frame-advance labels, not physical NES beam or CPU-cycle timing.
- The replay used the retained opening inputs for frames 0–4692 and the existing title-to-first-menu input trace for frames 4693–9042. The replayed frame-9042 CPU RAM and PPU memory matched the retained endpoint bytes exactly.
- The extended local trace artifacts are under `/tmp/ct2_first_pass_action_next_menu/`; these are validation evidence only and are not runtime resources.
